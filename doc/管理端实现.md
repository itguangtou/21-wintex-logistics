# Wintex 管理端实现计划

> 目标：全站各页内容可在 `/admin` 后台编辑；文案支持中英文；图片可上传。  
> 文档版本：2026-08-11

---

## 〇、确认结论

| 项 | 结论 |
|----|------|
| 中英文 | 业务内容字段保留中英（`zh` / `en` 或 `{ zh, en }`），与 next-intl 的 UI 文案分离 |
| UI i18n | 导航按钮等仍用 `messages/*.json`，不进 CMS |
| 内容 i18n | 首页/关于/新闻/招聘等进数据库，后台左右栏编辑中英 |
| 组织方式 | **以页面/模块为单位**管理 |
| 图片 | Supabase Storage + `media` 表 |

## 一、前端 UI（优先）

### 1.1 整体布局（你指定的结构）

```
┌────────────────────────────────────────────────────────────┐
│  Logo / 站点名     │  顶栏 Head（当前模块名、用户、退出）   │
│  ───────────────   ├───────────────────────────────────────┤
│  侧栏菜单          │                                       │
│  · 首页            │   Body                                │
│  · 关于我们        │   ┌ 搜索 / 筛选 / 新建 ─────────────┐ │
│  · 实力见证        │   └─────────────────────────────────┘ │
│  · 装备清单        │   ┌ 列表区域 ───────────────────────┐ │
│  · 新闻            │   │  行数据 / 卡片 / 分页            │ │
│  · 招聘            │   └─────────────────────────────────┘ │
│  · 站点设置        │                                       │
│  · 媒体库（可选）  ├───────────────────────────────────────┤
│                    │  底栏 Foot（保存、发布、提示信息）     │
└────────────────────────────────────────────────────────────┘
```

| 区域 | 位置 | 职责 |
|------|------|------|
| **Logo + 菜单栏** | 左侧固定 | Logo、名称「Wintex 管理端」、模块导航 |
| **Head** | 右侧上方 | 当前模块标题、面包屑、登录用户、退出 |
| **Body** | 右侧中部 | **搜索区 + 列表区**（主工作区） |
| **Foot** | 右侧下方 | 主操作：保存草稿、发布、批量删除等 |

### 1.2 路由结构

```

/admin/pages/home           首页内容编辑

/admin/pages/equipment      装备页（页头 + 链到装备列表）

/admin/equipment-items      装备条目列表
/admin/careers              招聘管理（现有能力迁入）
/admin/settings             站点设置（联系方式 / SEO）
/admin/media                媒体库（可选）
```

### 1.3 Body 两种形态

#### A. 列表型模块（新闻、装备、时间轴、媒体）

```
Body
├── 搜索区
│   ├── 关键词输入
│   ├── 状态筛选（全部 / 已发布 / 草稿）
│   ├── 语言提示（列表展示可用当前预览语言）
│   └── [新建] 按钮
└── 列表区
    ├── 表头：标题 / 更新时间 / 状态 / 操作
    ├── 行：点击进入编辑
    └── 底部分页
```

#### B. 单页编辑型模块（首页、关于我们、站点设置）

```
Body
├── 搜索区（可弱化为「区块快速定位」或隐藏）
│   └── 锚点：Hero / 介绍 / 实力 …
└── 列表区（改为「区块卡片列表」）
    ├── 卡片：Hero（中英字段 + 图片）
    ├── 卡片：介绍
    └── …
Foot：保存 / 发布
```

招聘模块沿用现有表单逻辑，套进同一套壳（左菜单 + 右 Head/Body/Foot）。

### 1.7 前端实现顺序

1. 抽离通用 `AdminShell`（左菜单 + 右 Head/Body/Foot）
2. 菜单项先全部挂上，未做模块显示「敬请期待」或禁用
3. 先做 **新闻列表页**（搜索 + 列表 + 新建），验证壳子
4. 再做 **首页单页编辑**（区块卡片）
5. 招聘迁入 `/admin/careers`
6. 其余页面与列表模块跟进

## 二、中英文内容设计

### 2.1 原则

- **UI 文案**：继续 next-intl（`messages/zh.json`、`en.json`）
- **可运营内容**：入库，每个文案字段带中英

### 2.2 字段形态（推荐）

JSON 内统一：

```json
{
  "title": { "zh": "中文标题", "en": "English Title" },
  "body": { "zh": "...", "en": "..." },
  "image": "/images/hero.png"
}
```

表列扁平时也可用：`title_zh` / `title_en`（新闻表已有类似结构）。

管理端用 `BilingualField`：左侧中文、右侧英文，同一逻辑字段。

### 2.3 语言与招聘兼容

- 新模块统一 `zh` / `en`
- 招聘现有 `cn` / `en`：接口层兼容，展示时映射 `cn ↔ zh`

## 三、后端与数据库

### 3.1 表一览

| 表 | 作用 | 单位 |
|----|------|------|
| `pages` | 整页 JSON（home/about/mission/equipment 页头等） | **一页一条** |
| `news` | 新闻 | 多条列表 |
| `equipment` | 装备条目 | 多条列表 |
| `timeline_items` | 使命时间轴 | 多条列表 |
| `careers_data` | 招聘整包 | 已有 |
| `site_settings` | 全局联系/SEO | key-value |
| `media` | 图片元数据 | 文件级 |
| `admin_users` | 管理员 | 已有 |

### 3.2 `pages`（页面为单位）

```sql
CREATE TABLE pages (
  slug TEXT PRIMARY KEY,           -- home | about | mission | equipment
  title_zh TEXT,
  title_en TEXT,
  content_zh JSONB NOT NULL DEFAULT '{}',
  content_en JSONB NOT NULL DEFAULT '{}',
  status TEXT NOT NULL DEFAULT 'published',  -- draft | published
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  updated_by TEXT
);
```

**home 的 content 示例：**

```json
{
  "hero": {
    "title": { "zh": "...", "en": "..." },
    "subtitle": { "zh": "...", "en": "..." },
    "desc": { "zh": "...", "en": "..." },
    "image": "https://xxx.supabase.co/storage/v1/object/public/media/pages/home/hero.jpg"
  },
  "intro": { "...": "..." },
  "strength": { "...": "..." }
}
```

> 若沿用已有 `page_sections`，也可用 `(page_slug, section_key)` 多行；**更推荐 `pages` 整页一条**，与「以页面为单位」一致。

### 3.3 列表表（已有可沿用）

**news**

- `id`, `title_zh`, `title_en`, `content_zh`, `content_en`
- `image_url`, `published_at`, `sort_order`, `is_published`, `updated_at`

**equipment**

- `id`, `name_zh`, `name_en`, `description_zh`, `description_en`
- `image_url`, `sort_order`, `updated_at`

**timeline_items**

- `id`, `year`, `project_name_zh/en`, `description_zh/en`
- `parent_group`, `sort_order`, `updated_at`

**careers_data**

- `id = 'main'`, `data` JSONB（jobs + contact）

**site_settings**

- `key`, `value` JSONB

### 3.4 `media`

```sql
CREATE TABLE media (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  path TEXT NOT NULL,
  url TEXT NOT NULL,
  filename TEXT,
  mime TEXT,
  size INT,
  page_slug TEXT,
  alt_zh TEXT,
  alt_en TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 四、图片存储

### 4.1 方案

- **Supabase Storage** Bucket：`media`（Public）
- 路径约定：
  - `pages/{slug}/{section}.jpg`
  - `news/{id}/cover.jpg`
  - `equipment/{id}.jpg`

### 4.2 流程

```
管理端选图 → POST /api/upload（需登录）
  → 上传 Storage
  → 写 media 表
  → 返回 url
  → 写入页面/新闻字段
```

### 4.3 说明

- Vercel 生产环境**不能**往 `public/` 写文件
- 旧图可继续用仓库内 `/images/...`；新上传走 Storage
- 后期可批量迁移旧图到 Storage

## 五、API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET/PUT | `/api/pages/[slug]` | 页面读写（PUT 需登录） |
| GET/POST | `/api/news` | 新闻列表/创建 |
| GET/PUT/DELETE | `/api/news/[id]` | 新闻详情 |
| GET/POST | `/api/equipment` | 装备 |
| GET/POST | `/api/timeline` | 时间轴 |
| GET/PUT | `/api/careers` | 招聘（已有，写需登录） |
| GET/PUT | `/api/site-settings` | 全局设置 |
| POST | `/api/upload` | 上传图片 |
| GET | `/api/media` | 媒体列表 |
| POST | `/api/auth/login` 等 | 已有 |

前台：优先读库；无数据时 fallback 现有硬编码，便于分模块上线。

## 八、安全与权限

- 所有写接口、上传：校验 Cookie 会话（已有 `admin_users`）
- 读接口：前台公开可读；后台列表同样可读
- Storage：服务端用 `SERVICE_ROLE` 上传；前端只拿返回的 public URL
